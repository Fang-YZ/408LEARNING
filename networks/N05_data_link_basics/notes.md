## 一、30 秒速览

- **链路（link）vs 数据链路（data link）**：链路是物理线路；数据链路 = 物理线路 + **实现通信协议的硬件和软件**。
- 数据链路层的**五大功能**：① 为网络层提供服务 ② **组帧（成帧）** ③ **差错控制** ④ **流量控制** ⑤ **介质访问控制**。
- **组帧四种方法**：字符计数法、**字节填充法**（转义字符）、**零比特填充法**（HDLC：连续 5 个 1 后插 0）、**违规编码法**。
- **检错 vs 纠错**：检错码（奇偶校验、CRC）**只能发现错误**；纠错码（**海明码**）能**定位并纠正**。
- **奇偶校验**：只能检出**奇数个**错误，偶数个错误检不出；检错能力弱但开销最小。
- **CRC 核心**：`r = deg(G)`；被除数 = 数据位 + r 个 0；**模 2 除法（逐位 XOR，不借位）**得 r 位余数；**码字 = 数据位 ‖ 余数**。
- **CRC 验收**：接收方把整个码字再除以 G，**余数为 0 就认为没错**。
- **CRC 能力**：能检出**所有单比特错、所有奇数个错（G 含 (x+1) 因子时）、所有长度 ≤ r 的突发错**（考点）。

## 二、本课知识点（完整版）

### 2.1 数据链路层的功能

| 功能 | 说明 |
| --- | --- |
| 为网络层提供服务 | 无确认无连接 / 有确认无连接 / 有确认面向连接（按需求选） |
| **组帧（成帧）** | 把比特流切分成一个个**帧**，使接收方能识别帧的开始与结束 |
| **差错控制** | 用**检错码/纠错码**应对传输中的比特错误（本课重点） |
| **流量控制** | 控制发送方速率，别把接收方缓冲撑爆（N6 展开） |
| **介质访问控制** | 决定共享介质上"谁能发、什么时候发"（N7 展开） |

**为什么必须组帧**：物理层只送比特流，没有边界概念。若不组帧，接收方无法知道哪些比特属于哪一帧、哪里是首部哪里是数据。

> **透明传输**：无论数据部分出现什么比特组合，都必须能正确传输而不被误认为帧边界。**字节填充/零比特填充就是为了实现透明传输。**

### 2.2 组帧（成帧）的四种方法

| 方法 | 做法 | 优点 | 缺点/考点 |
| --- | --- | --- | --- |
| **字符计数法** | 帧首部用一个计数字段**标明帧内字符数** | 简单 | **一个计数出错就全乱**：后续帧边界全部错位（致命缺点） |
| **字节填充法** | 用特殊字符（如 `SOH`/`EOT`）定界；数据中出现的定界符前**插入转义字符 ESC** | 可透明传输 | 转义字符本身也要转义；面向**字节**，不适合任意比特流 |
| **零比特填充法** | 定界符 `01111110`；发送方在数据中**每遇到连续 5 个 1 就插入一个 0**；接收方收到 5 个 1 后若下一个是 0 就删掉 | **比特级透明**，HDLC/PPP 使用 | 考点：**发送方"5 个 1 插 0"，接收方"5 个 1 删 0"** |
| **违规编码法** | 用编码中**不会出现的电平**（违规码）表示帧开始/结束 | 无需填充，如曼彻斯特编码用高-高、低-低 | 依赖具体编码方案，如局域网 |

> **必背口诀**：计数法——**错一个全乱**；零比特填充——**"5110"**（连续 5 个 1 后插 0）。

### 2.3 差错控制：检错与纠错

| 类型 | 代表编码 | 能力 | 开销 |
| --- | --- | --- | --- |
| **检错编码** | 奇偶校验码、**CRC 循环冗余码** | 只能**发现**错误（接收方可请求重传） | 小 |
| **纠错编码** | **海明码**、卷积码 | 能**定位并纠正**错误 | 大（冗余多） |

**① 奇偶校验码**

- 奇校验：让码字中 1 的个数为**奇数**；偶校验：为**偶数**。
- 只能检出**奇数个**比特错误；**偶数个错误完全检不出**（这是最常见的坑）。
- 二维奇偶校验可检出并纠正部分错误。

**② CRC 循环冗余校验（本课重点，必须会手算）**

**手算四步（记牢）**：

```
设数据 M（k 位），生成多项式 G（n+1 位），则 r = n = deg(G) = strlen(G) - 1

第 1 步：在 M 后面补 r 个 0                 -> 得到 k + r 位被除数
第 2 步：用模 2 除法（逐位 XOR，不借位）除以 G
第 3 步：余数就是 r 位的 CRC 校验码（不足 r 位前面补 0）
第 4 步：发送的码字 = M ‖ 余数（共 k + r 位）
```

**接收方验收**：把收到的整个码字再除以同一个 G，**余数为 0 → 认为无错**；非 0 → 出错，丢弃（或请求重传）。

**CRC 的检错能力（选择题高频）**：

| 能力 | 条件 |
| --- | --- |
| 检出**全部单比特**错误 | 一定能（只要 G 不止一项） |
| 检出**全部奇数个**比特错误 | G 中**含有 (x+1) 因子**时 |
| 检出全部**长度 ≤ r** 的突发错误 | 一定能 |
| 检出**大部分**长度 = r+1 的突发错误 | 概率性 |
| 长度 > r+1 的突发错误 | 以 1 − (1/2)^r 的概率检出 |

**③ 海明码（纠错编码）**

- 校验位位数 r 满足：`2^r ≥ k + r + 1`（k 为数据位位数）。
- 校验位放在 **2 的幂次位置**（1、2、4、8…），其余位置放数据位。
- 通过**各校验组的异或结果**（称为"伴随式"）指出出错位的**二进制位置**，取反即纠正。

## 三、代码模板

### 3.1 CRC 校验器（手算过程的程序版）

`networks/N05_data_link_basics/examples/crc_check.c`

```powershell
gcc -Wall -Wextra -O2 -o crc_check.exe crc_check.c
.\crc_check.exe                          # 默认数据 1101011011、生成多项式 10011
.\crc_check.exe 101001 1101              # 自定：<数据位> <生成多项式位>
```

**实测输出（教材经典例题，可对拍）**：

```
data_length        = 10 bit
generator_degree_r = 4
divided_bits       = 11010110110000
remainder          = 1110
codeword           = 11010110111110
codeword_length    = 14 bit
receiver_remainder = 0000
verdict            = OK (remainder is zero)
```

即：数据 `1101011011` + 余数 `1110` → 码字 `11010110111110`（14 位）。**接收方再除一次，余数 0000 → 判定无错。**

核心代码（模 2 除法，逐位 XOR）：

```c
unsigned long long R = data_int;                 /* data_int = M 左移 r 位（补 r 个 0） */
int k;
for (k = mlen + r; k >= r; k--) {                /* 从左到右逐位对齐 G 的最高位 */
    if ((R >> k) & 1ULL) {                       /* 当前位是 1 才做 XOR */
        R ^= (G << (k - r));                     /* 模 2 减法 = 异或，不借位 */
    }
}
/* 循环结束后，R 的低 r 位就是余数 */
```

## 四、坑清单

| # | 坑 | 正解 |
| --- | --- | --- |
| 1 | 认为奇偶校验能检出所有错误 | 只能检出**奇数个**错误；**偶数个错误检不出** |
| 2 | 把 CRC 当成纠错码 | CRC 是**检错码**，只能发现错误（要纠错用海明码） |
| 3 | 忘记补 r 个 0 | 必须先在数据后补 `r = deg(G)` 个 0，再去除 |
| 4 | 余数位数写错 | 余数固定 **r 位**，不足要**前面补 0**（如 r=3 时余 `1` 要写成 `001`） |
| 5 | 模 2 除法用"借位减法" | 模 2 除法是**逐位 XOR**（异或），**不借位**；这是最容易算错的一步 |
| 6 | 误以为 CRC 能纠正错误 | 只能**检测**；重传由上层协议（如 GBN/SR）负责 |
| 7 | 零比特填充方向记反 | **发送方**：连续 5 个 1 后**插 0**；**接收方**：连续 5 个 1 后**删 0** |
| 8 | 认为字符计数法很可靠 | **一个计数字段出错会导致后续帧全部错位**，是最不可靠的组帧法 |
| 9 | 混淆"链路"与"数据链路" | 链路 = 物理线路；数据链路 = 物理线路 **+ 协议硬件与软件** |
| 10 | 认为组帧只是为了"好看" | 组帧是为了**划出边界 + 实现透明传输**，否则接收方无法定界 |
| 11 | 海明码校验位位置记错 | 校验位放在 **2 的幂次位置**（1、2、4、8…），数据位填其余位置 |
| 12 | 认为 G 越长越好 | G 越长冗余越大（r 位开销）；工程上要在检错能力与开销之间折中 |
