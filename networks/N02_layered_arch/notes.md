## 一、30 秒速览

- **分层的本质**：网络通信太复杂，把它拆成若干层，每层只解决一类问题，且只与对方**对等层**"对话"（对等通信）。
- **三大好处**：① 各层**独立**，某层技术换代不影响其他层；② **灵活性好**（可单独换实现）；③ 便于**标准化**与故障定位。
- **协议三要素**：**语法**（格式）、**语义**（含义/动作）、**同步**（事件顺序）——选择题高频。
- **协议 vs 服务 vs 接口**：协议是**水平的**（对等层之间的规则，对上层不可见）；服务是**垂直的**（下层向上层提供的能力，通过接口使用）。
- **OSI 七层**（自下而上）：**物–数–网–传–会–表–应**；**TCP/IP 四层**：网络接口层 / 网际层 / 传输层 / 应用层。
- **五层 PDU 名称**：应用层=**报文 message**，传输层=**报文段 segment**（TCP）/ 用户数据报（UDP），网络层=**分组/数据报 packet**，数据链路层=**帧 frame**，物理层=**比特 bit**。
- **数据封装**：自上而下**逐层加首部**（帧还加尾部 FCS）；接收方自下而上**逐层剥首部**。首部是**给对端同一层看的**。
- **三层"谁负责"**：端到端（进程↔进程）→ **传输层**；点到点（结点↔结点）→ **数据链路层**；选路 → **网络层**。
- **三张地址表**：MAC 地址（链路层，一跳内有效）/ IP 地址（网络层，端到端寻址）/ 端口号（传输层，定位进程）。

## 二、本课知识点（完整版）

### 2.1 为什么分层

| 视角 | 不分层的问题 | 分层之后 |
| --- | --- | --- |
| 工程复杂度 | 一个程序同时管网卡、选路、重传、字符编码 | 每层只管一类问题 |
| 技术演进 | 换 WiFi 要改浏览器 | 物理层换介质，应用层无感 |
| 标准化 | 各厂商无法互通 | 每层可独立标准化（IEEE 802 管下两层，IETF 管上三层） |
| 排障 | 出问题无从下手 | 按层定位（ping 通不通 / 端口通不通 / 应用报不报错） |

一句话：分层 = 把"端到端可靠传输"这个大问题，拆成一串各层能独立解决的小问题。

### 2.2 OSI 七层 vs TCP/IP 四层 vs 教学五层

| OSI 七层 | TCP/IP 四层 | 教学五层 | 典型协议 | 典型设备 | PDU |
| --- | --- | --- | --- | --- | --- |
| 应用层 / 表示层 / 会话层 | **应用层** | 应用层 | HTTP、DNS、SMTP、FTP、DHCP | 网关、代理 | 报文 message |
| 传输层 | **传输层** | 传输层 | TCP、UDP | —（端系统内） | 报文段 segment |
| 网络层 | **网际层** | 网络层 | IP、ICMP、ARP\*、OSPF、BGP | 路由器 | 分组 packet |
| 数据链路层 | **网络接口层** | 数据链路层 | 以太网、PPP、802.11、STP | 交换机、网桥、网卡 | 帧 frame |
| 物理层 | **网络接口层** | 物理层 | RS-232、10Base-T、光纤规格 | 中继器、集线器 | 比特 bit |

> \* **ARP 的归属是经典争议点**：408 主流教材（谢希仁 / 王道）把 ARP 放在**网络层**（它按 IP 地址工作，但其请求/应答报文封装在**帧**里，所以链路层的题面也会出现它）。
> **答题口径**：问「网络层协议」要能答出 ARP；问「ARP 报文封装在哪一层的 PDU 里」要答**以太网帧**。

**OSI 各层一句话职责**：

| 层 | 职责关键词 |
| --- | --- |
| 物理层 | 比特流传输、接口机械/电气/功能/规程特性（**不关心比特的含义**） |
| 数据链路层 | 成帧、差错控制、流量控制、介质访问（**相邻结点**之间的可靠传输） |
| 网络层 | 选路与转发、拥塞控制、异构网互连（**分组从源到目的**） |
| 传输层 | **端到端**、进程到进程、复用/分用、可靠或不可靠（TCP/UDP） |
| 会话层 | 会话建立/管理/同步（对话控制） |
| 表示层 | 数据格式、加密、压缩（**语法**转换） |
| 应用层 | 面向具体应用的协议（用户能直接感知） |

### 2.3 协议 · 接口 · 服务（最容易混的一组概念）

| 概念 | 方向 | 定义 | 记忆点 |
| --- | --- | --- | --- |
| **协议** | 水平（对等层之间） | 同层实体通信必须遵守的规则集合 | 协议是"**给同层看的**"，对上层**透明/不可见** |
| **服务** | 垂直（下层→上层） | 下层通过层间接口向上层提供的**能力** | 服务是"**给上层用的**"，只描述"能做什么"，不暴露"怎么做" |
| **接口（SAP）** | 垂直 | 上下层交换信息的**入口**（服务访问点） | 同一结点内相邻层之间 |

三条必背判断句：

1. **协议是水平的，服务是垂直的**——协议在对等层之间，服务在相邻层之间。
2. **上层使用下层提供的服务，但看不到下层的协议**（协议对上层透明）。例：浏览器用 TCP 的服务，但不需要知道 TCP 怎么重传。
3. **服务原语**四类：**请求 Request → 指示 Indication → 响应 Response → 确认 Confirm**（简答写这 4 个词基本能拿分）。

### 2.4 数据封装与解封装（本课核心，必考）

发送方自上而下，**每层加本层首部**（链路层还加尾部 FCS）：

```
应用层数据:                 [        DATA        ]                      报文
传输层(加 TCP 首部):   [TCP首部][      DATA      ]                      报文段
网络层(加 IP 首部):  [IP首部][TCP首部][  DATA   ]                       分组
链路层(加帧头帧尾): [帧头][IP][TCP][DATA][FCS]                          帧
物理层:            ~~~~~~ 0101 0101 0101 ~~~~~~                        比特
```

接收方自下而上，**每层剥掉自己的首部**交给上层，最后应用程序拿到 DATA。

**关键洞察**：每个首部都是**给对端同一层准备的**。对端网卡只读帧头和 FCS，不会去读 HTTP；
所以换网线不影响浏览器 —— 这就是"分层独立"的价值。

> ⚠️ **帧的尾部**：链路层是唯一**既加首部又加尾部**的层（尾部是 4 字节 FCS/CRC 校验）。这是高频选择题点。

### 2.5 各层的数据单位与地址（对照记）

| 层 | 数据单位（PDU） | 该层使用的地址 | 地址作用范围 |
| --- | --- | --- | --- |
| 应用层 | 报文 message | 域名 / URL | 全局 |
| 传输层 | 报文段 segment / 用户数据报 datagram | **端口号** | 主机内定位进程 |
| 网络层 | 分组 packet | **IP 地址** | 全局（跨网络端到端） |
| 数据链路层 | 帧 frame | **MAC 地址** | 本网段（一跳之内） |
| 物理层 | 比特 bit | 无 | — |

> 记忆链：**端口找进程，IP 找主机，MAC 找网卡**。

### 2.6 数据流动的全过程（简答题万能骨架）

以"你的电脑访问 `http://example.com`"为例，数据自上而下经过发送方五层，再自下而上穿过接收方五层：

1. **应用层**：浏览器生成 HTTP 请求报文。
2. **传输层**：加 TCP 首部（含源/目的**端口**），交给网络层。
3. **网络层**：加 IP 首部（含源/目的 **IP 地址**），查路由表决定下一跳。
4. **数据链路层**：加帧头（含源/目的 **MAC 地址**）和帧尾 FCS；由网卡发送。
5. **物理层**：转成比特流送到介质上传输。
6. 中途每经过一个**路由器**：剥到**网络层**（换 IP 首部中的生存时间等），再重新封装成新的帧（**换 MAC 地址，不换 IP 地址**）。
7. 到达目的主机后逐层**解封装**，最终交给服务器上的 Web 进程（由**目的端口**分用定位）。

> 答题得分点：**路由器只处理到网络层；交换/网桥处理到链路层；集线器/中继器只到物理层**。
> 这也解释了为什么"路由器隔离广播域、交换机隔离冲突域"。

### 3.1 概念示例：用 socket 看"分层"（把抽象变成看得见的东西）

运行方式（PowerShell，工作目录 `E:\learn408\networks\N02_layered_arch\examples`）：

```powershell

.\ex1_echo_server.exe 9000
```

另一个终端当客户端：

```powershell
gcc -Wall -Wextra -O2 -o ex2_echo_client.exe ex2_echo_client.c -lws2_32
.\ex2_echo_client.exe 127.0.0.1 9000 tcp
```

实测输出（英文，本笔记数据为真实运行所得）：

客户端：

```
CONNECTED 127.0.0.1:9000
SENT 4 bytes
REPLY: ACK 4: tcp
CLOSED
```

服务器：

```
ECHO SERVER READY on port 9000
CONNECTED from 127.0.0.1:<临时端口>
RECV 4 bytes -> tcp
DISCONNECTED
```

**这里要看的"分层"是什么**：服务器程序（应用层）只读写 `tcp` 这 3 个字节，
它完全不知道这些字节在下面被封装成报文段、分组、帧、比特；也不知道中途经过了几跳、丢没丢、重传了几次。
**那些都是传输层及以下的事** —— 这就是分层给应用层带来的"免于复杂度"。

### 3.2 TCP 服务端七步骨架（背下来，N11 传输层还要用）

```c
#define _WIN32_WINNT 0x0600          /* 必须在 winsock2.h 之前，否则 inet_ntop 未声明 */
#include <winsock2.h>
#include <ws2tcpip.h>

WSAStartup(MAKEWORD(2, 2), &wsa);                          /* 1. 初始化 Winsock（Windows 专属） */
listen_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);   /* 2. 建套接字：AF_INET=IPv4, SOCK_STREAM=TCP */
bind(listen_sock, (struct sockaddr *)&addr, sizeof(addr)); /* 3. 绑定 本机IP:端口（服务器必须 bind） */
listen(listen_sock, SOMAXCONN);                            /* 4. 转为被动监听 */
conn = accept(listen_sock, (struct sockaddr *)&peer, &plen);/* 5. 取出一个已完成连接（阻塞点） */
recv(conn, buf, len, 0);  send(conn, buf, len, 0);         /* 6. 收发字节流 */
closesocket(conn); WSACleanup();                           /* 7. 关闭 */
```

**套接字 API 与分层模型的对应关系**（答题/面试常问）：

| API | 作用 | 对应模型中的位置 |
| --- | --- | --- |
| `socket(AF_INET, SOCK_STREAM, IPPROTO_TCP)` | 创建套接字，选定协议族与类型 | 传输层及以下的"通道" |
| `bind` / `listen` / `accept` | 服务器端固定端口、等待连接 | 传输层（端口 = 传输层地址） |
| `connect` | 客户端发起连接（TCP 三次握手在此发生） | 传输层 |
| `send` / `recv` | 读写**字节流** | 应用层与传输层之间的接口 |
| `inet_pton` / `htons` | IP 地址与端口号的表示转换 | 网络层地址 + 传输层端口 |

### 3.3 编译命令模板

```powershell
gcc -Wall -Wextra -O2 -o <输出名>.exe <源文件>.c -lws2_32
```

> `-lws2_32` 必须放**最后**，否则 MinGW 链接报 `undefined reference`。

## 四、坑清单

### 4.1 概念陷阱（408 选择题专坑）

| # | 坑 | 正解 |
| --- | --- | --- |
| 1 | 把"传输层"当"点到点" | 传输层是**端到端（进程到进程）**；**点到点**是数据链路层 |
| 2 | 以为每一层都加首部和尾部 | 只有**数据链路层**既加首部又加尾部（FCS） |
| 3 | 分不清 PDU 名称 | 报文 / 报文段 / 分组 / 帧 / 比特，**别用"数据包"混答** |
| 4 | 说"协议对上层是可见的" | 协议对上层**透明**（不可见）；上层只看见**服务** |
| 5 | 把 OSI 的"表示层"当成"加密层" | 表示层管**数据格式/语法转换**（加密压缩是其功能之一，但主要考点是格式转换） |
| 6 | 认为 TCP/IP 四层中有"会话层/表示层" | TCP/IP 把这三层合并进**应用层** |
| 7 | 说"路由器处理到传输层" | 路由器**最高只到网络层**；交换机到链路层；集线器只到物理层 |
| 8 | 混淆"协议是垂直的、服务是水平的" | **协议水平，服务垂直**（反过来说就错） |
| 9 | 忽略 ARP 的封装层 | ARP 按 IP 工作（归网络层），但**报文封装在以太网帧中** |
| 10 | 把 IP 地址与 MAC 地址的作用范围搞反 | IP 端到端全局；MAC 只在**本网段一跳内**有效，跨路由器会被改写 |

### 4.2 Windows + MinGW 编程实战坑（真踩过）

| # | 坑 | 现象 | 正确做法 |
| --- | --- | --- | --- |
| 11 | 头文件顺序 | `winsock2.h` 与 `windows.h` 冲突、重复定义 | 先 `#define _WIN32_WINNT 0x0600`，再 `#include <winsock2.h>`→`<ws2tcpip.h>`，**永不手写 `windows.h`** |
| 12 | 忘记链接库 | `undefined reference to 'WSAStartup@8'` | 编译命令末尾加 `-lws2_32` |
| 13 | 忘记 `WSAStartup` | `socket()` 返回 INVALID_SOCKET，错误码 **10093** | 进程启动先 `WSAStartup(MAKEWORD(2,2),&wsa)`，退出前 `WSACleanup()` |
| 14 | `inet_ntop` 未声明 | `implicit declaration of function 'inet_ntop'` | 缺 `#define _WIN32_WINNT 0x0600` |
| 15 | 端口被占用 | `bind() failed ... 10048` | 换端口，或给监听套接字设 `SO_REUSEADDR` |
| 16 | 把 `send()` 当"一定全发完" | 大数据偶发丢尾 | 循环发到全部发完（`send_all` 模式） |
| 17 | 把 TCP 当有"消息边界" | 一次 `recv` 收到两条消息或半条 | TCP 是**字节流**，必须自己定界（本课用 `\n`） |
| 18 | 端口号没转网络字节序 | 能连上却连到莫名其妙的地方 | `addr.sin_port = htons(port)`；IP 用 `inet_pton` |
| 19 | 中文输出到 Windows 终端 | 乱码 | 本课程程序输出**一律英文** |
| 20 | 重定向日志后看不到输出 | 输出文件是空的 | `setvbuf(stdout, NULL, _IONBF, 0)` 关缓冲 |
