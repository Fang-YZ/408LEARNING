## 一、30 秒速览

- **流量控制** = 别让发送方发得太快把接收方撑爆；**可靠传输** = 出错/丢失能恢复。两者都靠**滑动窗口**实现。
- 三个协议的关系：**停止-等待 = 窗口为 1 的滑动窗口**；**GBN 与 SR 是两种滑窗实现**。
- **核心比值** `a = RTT / T_d`（T_d = 帧发送时延 = L/R）：一个往返时间里能塞进多少帧。
- **保持链路不停的最小窗口**：`W_need = 1 + a`（`a = RTT/T_d`；等价于 `W·T_d ≥ T_d + RTT`）。
- **窗口上限与序号位数 n 的关系（必背）**：**GBN ≤ 2ⁿ − 1**；**SR ≤ 2ⁿ⁻¹**（收发窗口之和 ≤ 2ⁿ）。
- **利用率**：停等 `U = 1/(1+a)`；GBN/SR `U = min(1, W/(1+a))`（`a = RTT/T_d`；另有 `a=RTT/(2Td)` 的等价写法见 3.1）。
- **出错时行为**：GBN **丢弃乱序帧 + 重传从出错帧起的整个窗口**（累积确认）；SR **缓存乱序帧 + 只重传出错帧**（逐帧确认）。
- **接收窗口**：停等 = 1；GBN = 1；**SR = W（与发送窗口相同）**。

## 二、本课知识点（完整版）

### 2.1 流量控制与可靠传输的三种机制

| 机制 | 说明 |
| --- | --- |
| **停止-等待（Stop-and-Wait）** | 发一帧 → 等确认 → 再发下一帧。**信道利用率极低** |
| **后退 N 帧（GBN）** | 连续发多帧；接收方**只按序接收**，出错则从该帧起**全部重传** |
| **选择重传（SR）** | 连续发多帧；接收方**缓存乱序帧**，**只重传出错的那一帧** |

> **一句话区分 GBN 与 SR**：GBN 是"**一个坏了全重来**"，SR 是"**只补发坏的那个**"。
> 代价：SR 需要**接收缓存**和**逐帧确认**，实现更复杂。

### 2.2 停止-等待协议（含四种出错情形）

| 情形 | 处理 |
| --- | --- |
| 数据帧正确到达 | 接收方回 ACK，发送方发下一帧 |
| 数据帧出错/丢失 | 发送方**超时重传** |
| ACK 丢失 | 发送方超时重传 → 接收方收到**重复帧** → 需**给帧编号**并丢弃重复帧 |
| ACK 迟到 | 同样的帧编号机制可识别 |

**为什么必须给帧编号**：否则接收方无法区分"新帧"与"重传的旧帧"。
**停等的序号只需 1 位**（0/1 交替即可）。

**利用率**：设 T_d = 帧发送时延、RTT = 往返时间：

```
U = T_d / (T_d + RTT) = 1 / (1 + a)     其中 a = RTT / T_d
```

### 2.3 滑动窗口的三个窗口

| 名称 | 含义 |
| --- | --- |
| 发送窗口 W_T | 发送方**已发送但未收到确认**的帧的序号范围 |
| 接收窗口 W_R | 接收方**允许接收**的帧的序号范围 |
| 序号空间 | 由序号位数 n 决定，共 **2ⁿ** 个序号 |

**窗口滑动规则**：收到确认后窗口向前滑动；**窗口大小固定**（不是慢慢变大）。

### 2.4 GBN 与 SR 的窗口约束（必背，考试高频）

| 协议 | 发送窗口 W_T | 接收窗口 W_R | 约束条件 | 理由 |
| --- | --- | --- | --- | --- |
| 停止-等待 | 1 | 1 | 2¹ = 2 ≥ 1+1 | — |
| **GBN** | ≤ **2ⁿ − 1** | **1** | W_T ≤ 2ⁿ − 1 | 接收窗口恒为 1，确认是累积的 |
| **SR** | ≤ **2ⁿ⁻¹** | **= W_T** | W_T + W_R ≤ 2ⁿ | 收发窗口相同，故各占一半 |

> **推导要点（SR）**：若 W_T + W_R > 2ⁿ，接收方无法区分"新一批帧"与"重传的旧帧"，会收错。
> **GBN 为什么是 2ⁿ−1 而不是 2ⁿ**：接收窗口为 1，若 W_T = 2ⁿ，全部 ACK 丢失时接收方无法区分新旧帧。

### 2.5 出错与乱序时的行为对照

| 事件 | GBN | SR |
| --- | --- | --- |
| 某帧出错/丢失 | **丢弃该帧及其后所有帧** | **缓存后续正确帧** |
| 重传范围 | 从出错帧起**整个发送窗口**（W 个） | **只重传出错的那一帧** |
| 确认方式 | **累积确认**（ACK n 表示 n 及之前全部收到） | **逐帧确认**（每个帧单独确认） |
| 接收缓存 | 不需要 | **需要** |
| 计时器 | 只需**一个**（最早未确认帧） | **每帧一个** |

**窗口内第 k 帧丢失时的重传帧数**（本课示例会算）：

```
GBN：W − k + 1 个（k 在窗口内时）；k 不在窗口内则该轮无需重传
SR ：始终只重发 1 个
```

### 2.6 利用率与"窗口够不够"

**本课统一口径**（推导见第三节 3.1，记住推导就不会记错公式）：

```
a = RTT / T_d                       （一个往返时间里能容纳多少个帧的发送时间）
W_need = 1 + a                      （让链路一直有帧在传的最小窗口）
U = min(1, W / (1 + a))             （GBN/SR；停等取 W = 1）
若 最大允许窗口 < W_need → 链路出现空闲，U = W_max / (1 + a)
```

**典型考题形态**：给 T_d、RTT、序号位数 n，问"GBN/SR 的最大利用率是多少"→
先算 `1 + a`，再取 `min(1, (2ⁿ−1)/(1+a))` 或 `min(1, 2ⁿ⁻¹/(1+a))`。

> 若题目把 `a` 定义成 **`RTT/(2·T_d)`**（单程传播口径），公式就写成 `1 + 2a` —— **含义完全相同**，
> 只是同一个物理量换了单位。判断方法：看题目给的 `a` 定义式，或直接**用 T_d 与 RTT 现算**，别背两套。

## 三、代码模板

### 3.1 窗口与利用率计算器

`networks/N06_flow_reliable/examples/sliding_window.c`

```powershell
gcc -Wall -Wextra -O2 -o sliding_window.exe sliding_window.c
.\sliding_window.exe                             # 默认 n=3, Td=1ms, RTT=4ms, 丢第 1 帧
.\sliding_window.exe <n_bits> <Td_ms> <RTT_ms> <lost_index>
```

**实测输出（默认参数，可对拍）**：

```
seq_space_2n       = 8
a_ratio_RTT_over_Td= 4.000000
window_needed      = 5
gbn_max_window     = 7
sr_max_window      = 4
util_stop_and_wait = 0.200000
util_gbn           = 1.000000
util_sr            = 0.800000
resend_on_loss_gbn = 7
resend_on_loss_sr  = 1
note               = GBN is enough, SR window is too small
```

读法：Td=1ms、RTT=4ms → `a = RTT/Td = 4` → **需要窗口 `W_need = 1 + a = 5`**。
GBN 上限 7 ≥ 5 → 能跑满（U=1）；SR 上限 4 < 5 → 只能到 `4/5 = 0.8`。
停等只有一个帧在传 → `U = 1/(1+a) = 1/5 = 0.2`。丢第 1 帧时 GBN 要重发 **7** 个，SR 只重发 **1** 个。

**推导（记这一条就够，不要背两套公式）**：

```
利用率 = 一个周期内"真正在发送帧"的时间 ÷ 周期总时间

停等：周期 = Td + RTT，发送时间 = Td
      U = Td/(Td+RTT) = 1/(1 + RTT/Td) = 1/(1+a)

滑窗：一个周期内可以连续发 W 个帧，周期 = Td + RTT
      U = W·Td/(Td+RTT) = W/(1+a)，且不超过 1

链路不停的条件：W·Td ≥ Td + RTT   ⟺   W ≥ 1 + a = W_need
```

> ⚠️ **关于教材里常见的 `1+2a` 写法**：那是另一个约定 —— 把 `a` 定义为 **`RTT/(2·Td)`**（即"单程传播时延相当于多少个帧的发送时间"）。
> 两者**不矛盾**，只是 `a` 的含义差一个 2 倍：
>
> | 约定 | a 的定义 | 停等利用率 | 需要窗口 |
> | --- | --- | --- | --- |
> | 本课（帧数口径） | `a = RTT/Td` | `1/(1+a)` | `1 + a` |
> | 部分教材（单程口径） | `a = RTT/(2·Td)` | `1/(1+2a)` | `1 + 2a` |
>
> **做题时以题目给的定义为准**；看到 `1+2a` 就用 `a=RTT/(2Td)`，看到 `1+a` 就用 `a=RTT/Td`。
> 本课示例程序输出里直接给的是 `a_ratio_RTT_over_Td`，就是为了让你一眼看出口径。

## 四、坑清单

| # | 坑 | 正解 |
| --- | --- | --- |
| 1 | 记成 GBN ≤ 2ⁿ、SR ≤ 2ⁿ⁻¹ | **GBN ≤ 2ⁿ−1**、**SR ≤ 2ⁿ⁻¹**（GBN 是减 1 的那个） |
| 2 | 以为 GBN 的接收窗口也是 W | GBN **接收窗口恒为 1**（只按序接收） |
| 3 | 以为 SR 的发送窗口可以到 2ⁿ⁻¹ 以上 | SR **收发窗口之和 ≤ 2ⁿ**，各占一半即 2ⁿ⁻¹ |
| 4 | 把 GBN 的确认说成逐帧确认 | GBN 是**累积确认**；SR 才是**逐帧确认** |
| 5 | GBN 出错时只重传那一帧 | GBN **重传出错帧及其后整个窗口** |
| 6 | SR 收到乱序帧就丢弃 | SR **缓存乱序帧**，这正是它比 GBN 高效的原因 |
| 7 | 混淆 `a` 的两种定义 | `a = RTT/T_d` 时公式是 `1+a`；`a = RTT/(2T_d)` 时是 `1+2a`。**看题目定义** |
| 8 | 忘记"滑动窗口大小是固定的" | 收到确认后窗口**整体前移**，大小不变（不是逐渐变大） |
| 9 | 认为停等不需要序号 | 停等**必须有 1 位序号**，否则无法识别重复帧 |
| 10 | 把流量控制与拥塞控制混为一谈 | 流量控制管**接收方**能力（端到端）；拥塞控制管**网络**负载（N12） |
| 11 | 计算利用率时忘记取 min(1, …) | 窗口足够大时利用率**上限是 1**，不会超过 100% |
| 12 | 认为 GBN 一定比 SR 差 | GBN 实现简单、**不需要接收缓存**；误码率低时 GBN 更实用 |
