## 一、30 秒速览

网络通信太复杂，所以**分层**——每层只解决一类问题，只和服务自己对等的层"对话"（对等通信），
上层把数据交给下层时**加上本层首部**（封装），到达对端后下层把首部剥掉交给上层（解封装）。

- 分层的两大好处：**各层独立**（技术换代不影响别人）、**灵活性好**（某层可单独换实现）。
- 必须记住的四层 PDU：应用层=**报文 message**，传输层=**报文段 segment**（TCP）/ 用户数据报 datagram（UDP），网络层=**分组/数据报 packet**，数据链路层=**帧 frame**，物理层=**比特 bit**。
- **协议三要素：语法、语义、同步**（考选择题的高频点）。
- 本课实验：一段 30 行的 socket 代码，让你亲眼看到"应用层的文本"变成网络上传输的字节流，而 TCP 负责把它完好送达。

## 二、核心概念

### 1. 为什么要分层

| 视角 | 不分层的问题 | 分层后 |
|---|---|---|
| 工程 | 一个程序要同时管网卡、路由、重传、汉字编码 | 每层只管一件事 |
| 演进 | 换 WiFi 就得改浏览器 | 物理层换介质，应用层无感 |
| 教学/考试 | 无从下手 | 可按层出题、按层排查 |

**一句话**：分层 = 把"端到端可靠传输"这种大问题，拆成一串各层能独立解决的小问题。

### 2. OSI 七层 vs TCP/IP 四层

| OSI 七层 | TCP/IP 四层 | 该层典型协议/设备 | PDU |
|---|---|---|---|
| 应用层 / 表示层 / 会话层 | **应用层** | HTTP、DNS、SMTP、FTP | 报文 message |
| 传输层 | **传输层** | TCP、UDP | 报文段 segment |
| 网络层 | **网络层** | IP、ICMP、ARP*、路由器 | 分组 packet |
| 数据链路层 | **网络接口层** | 以太网、PPP、交换机/网桥 | 帧 frame |
| 物理层 | **网络接口层** | 双绞线、光纤、中继器/集线器 | 比特 bit |

> \* ARP 的归属是经典争议点：408 教材把 ARP 放在**网络层**（它用 IP 地址工作，但报文封装在帧里）。

**OSI 记忆口诀（自下而上）**：物–数–网–传–会–表–应。
**"什么在哪儿"三连**：
- 端到端（进程到进程）由**传输层**负责；
- 点到点（一跳一跳）由**数据链路层**负责；
- 选路（路径决策）由**网络层**负责。

### 3. 协议三要素

| 要素 | 含义 | 例子 |
|---|---|---|
| 语法 | 数据与控制信息的**格式** | HTTP 请求行 `GET /index.html HTTP/1.1` |
| 语义 | 需要发出何种控制信息、完成何种动作 | `GET` 表示请求资源 |
| 同步 | 事件实现的**顺序** | TCP 三次握手：SYN → SYN+ACK → ACK |

### 4. 数据封装（本课核心，必考）

发送方自上而下，每层加首部：

```
应用层数据:                [ DATA ]
传输层(加 TCP 首部):  [TCP][ DATA ]                -> 报文段
网络层(加 IP 首部):   [IP][TCP][ DATA ]            -> 分组
链路层(加帧头帧尾): [FRAME][IP][TCP][DATA][FCS]    -> 帧
物理层:              ~~~~ 0101010101 ~~~~         -> 比特
```

接收方自下而上，每层剥掉自己的首部，最后把 DATA 交给应用程序。

**关键洞察**：首部是**为对等层准备的**——TCP 首部只有对端 TCP 才读，IP 首部只有对端 IP 才读。
所以你的浏览器不需要懂 IP 分片，网卡也不需要懂 HTTP。

```powershell
# 终端 A：启动服务器，监听 9000 端口

# 终端 B：用 Windows 自带的 telnet 当客户端（可选，telnet 需在"启用或关闭 Windows 功能"里打开）
telnet 127.0.0.1 9000
```

### 3.2 最小 TCP 服务端骨架（背下来，第 13 课还要用）

```c
#define _WIN32_WINNT 0x0600          /* 必须在 winsock2.h 之前，否则 inet_ntop 未声明 */
#include <winsock2.h>
#include <ws2tcpip.h>

WSAStartup(MAKEWORD(2,2), &wsa);             /* 1. 初始化 Winsock（Windows 专属） */
listen_sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);   /* 2. 建套接字：AF_INET=IPv4, SOCK_STREAM=TCP */
bind(listen_sock, ...);                       /* 3. 绑定 本机IP:端口（服务器必须 bind） */
listen(listen_sock, SOMAXCONN);               /* 4. 转为被动监听 */
conn = accept(listen_sock, ...);              /* 5. 取出一个已完成连接的套接字（阻塞点） */
recv(conn, ...);  send(conn, ...);            /* 6. 收发字节流 */
closesocket(conn); WSACleanup();              /* 7. 关闭 */
```

### 3.3 编译命令模板

```powershell
gcc -Wall -O2 -o <输出名>.exe <源文件>.c -lws2_32
```

> `-lws2_32` 必须放**最后**，否则 MinGW 链接会报 undefined reference。
> Windows 上写 socket 程序三件套：`#include <winsock2.h>`（要在 `windows.h` 之前）、`WSAStartup`、编译时 `-lws2_32`。

## 四、坑清单（Windows + MinGW 实战，都是真踩过的）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 头文件顺序 | `winsock2.h` 与 `windows.h` 冲突、重复定义 | `#define _WIN32_WINNT 0x0600` → `#include <winsock2.h>` → `#include <ws2tcpip.h>`，永不手写 `windows.h` |
| 2 | 忘记链接库 | `undefined reference to 'WSAStartup@8'` | 编译命令末尾加 `-lws2_32` |
| 3 | 忘记 WSAStartup | `socket()` 返回 INVALID_SOCKET，错误码 10093 | 进程启动先 `WSAStartup(MAKEWORD(2,2), &wsa)`，退出前 `WSACleanup()` |
| 4 | `inet_ntop` 未声明 | `implicit declaration of function 'inet_ntop'` | 少了 `#define _WIN32_WINNT 0x0600` |
| 5 | 端口被占用 | `bind() failed ... 10048` | 换端口，或对监听套接字设置 `SO_REUSEADDR`（示例里有） |
| 6 | 一台机器反复重启服务器 | 旧连接残留导致 bind 失败 | 同上，`SO_REUSEADDR` |
| 7 | 把 `send()` 当成"全发完" | 小数据没问题，大数据偶发丢尾 | `send()` 可能只发一部分，必须循环发完整长度（见 `send_all()`） |
| 8 | 把 TCP 当"消息边界" | 一次 recv 拿到两条消息，或半条消息 | TCP 是**字节流**，没有边界！要自己定界（本实验用 `\n` 定界） |
| 9 | 端口号没转网络字节序 | 能连上但连到莫名其妙的地方 | `addr.sin_port = htons(port)`，IP 用 `htonl`/`inet_pton` |
| 10 | 中文输出到 Windows 终端 | 乱码 | 本课程所有程序输出**一律英文** |
| 11 | 重定向日志后看不到输出 | 输出文件空 | 用 `setvbuf(stdout, NULL, _IONBF, 0)` 关缓冲 |
| 12 | 关服务器用 Ctrl+C | 端口没释放 | 强制关进程后等 1–2 秒，或直接换端口 |

**通关测试值（必须全部满足）：**

| 输入（text） | 期望 `ACK` 中的 n | 期望回显内容 |
|---|---|---|
| `tcp` | 4 | `ACK 4: tcp` |
| `TCP` | 4 | `ACK 4: TCP` |
| `a` | 2 | `ACK 2: a` |
| 空行（只按回车） | 1 | `ACK 1: ` |
| `network 408` | 12 | `ACK 12: network 408` |
| `AbC 123!`（改良版） | 9 | `ACK 9: ABC 123!` |

> ⚠️ 提醒：**测试要用已知正确答案的数据**。上表右侧就是标准答案，
> 你先自己算出预期值，再运行程序对比；不要"跑出什么就认为是对的"。
> `ACK n` 里的 n = **文本字节数 + 1**（把结尾的 `\n` 也算进去），
> 所以它正好等于客户端打印的 `SENT n bytes`——这是最常算错的地方：
> 空行也是**一次有效传输**，n = 1（不是 0，也不是 2）。
