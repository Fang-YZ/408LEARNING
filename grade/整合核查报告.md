## 四、批改流水线自测（预检器可信度证据）

用教练参考解假装"满分学员"，跑 `grade/check-lesson-01.ps1`：

```
PASS: 24    FAIL: 0    TOTAL: 24
MECHANICAL PRE-CHECK CLEAN.
```

覆盖：环境（gcc 探测）、答题卡体检（60 行 / 0 个未填字段 / 5 行答案）、编译零警告（4 个文件）、
**真机 socket 回归**（自己写 C 探针连学员的服务器，5 组已知数据 + 4 组大写版数据逐字节比对）、
客户端输出 4 行关键行比对、临时文件清理。

**判错分支也已验证**（不是只会打勾）：首次自测故意留着未填答题卡与 TODO，脚本正确报出
`CARD-1 FAIL（找不到答题卡）` 与 `BUILD-2 FAIL（剩余 TODO 3 个）`，并逐行给出要改哪里。

**过程中修掉的两个真 bug**（记录备查）：

| bug | 现象 | 修法 |
|---|---|---|
| 讲义数值自相矛盾 | 作业表写空行 `ACK 1:`，但参考服务器按"文本字节数"会输出 `ACK 0:` | 改**代码**而非改说法：协议定为 **n = 文本字节 + 1**（含结尾 `\n`），于是服务器 `ACK n` 与客户端 `SENT n bytes` 完全一致 |
| 讲义数值算错 | 作业表 `hello 408` 写期望 `ACK 9`（漏算 `\n`） | 全库改为 `ACK 10`，并核查 notes / 作业 / 提交说明 / 参考解 4 处一致 |
| 预检器中文乱码 | PowerShell 5.1 按 ANSI 读脚本，中文路径变 `绛旈鍗?txt` → 找不到答题卡 | 脚本改写为 **UTF-8 with BOM** |

## 五、待学员确认的一件事（唯一未决项）

现有 B 线顺序是 **N1 性能指标 → N2 分层体系**；我 09-28 的讲义把两者**对调**了（先分层、后性能指标）。
从 408 考纲看，两种顺序都合理（概念先行 vs 计算先行），但**不能同时存在**。

**教练建议：按现有体系走**（先 N1 后 N2），理由：

1. N1 已 100% 就绪（笔记 + 模板 + 自动批改脚本），学员随时可交；
2. A 线已用这套"N# 编号 + homework/N## 存档 + 自动批改"模式跑了 5 课，保持一致性成本最低；
3. 学习动线上，N1 的时延/带宽计算是后面所有层的"度量衡"，先建立度量再谈分层，做题更顺。

若学员更想先学分层（逻辑更"自上而下"），教练把现有 B 线 N1/N2 两行对调重编即可——**改编号，不动内容**。
